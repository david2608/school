# Pedanyan Brand Voice

Create new copy that carries a specific idea, uses verified facts, and sounds like an experienced designer and teacher rather than an education brand template.

## Required references

Read these repository files before writing:

1. `brand/VOICE.md`
2. `brand/CONTENT_RULES.md`
3. `brand/FACTS.md`
4. `brand/ANTI_FLUFF.md`

Read `brand/EXAMPLES.md` when the task needs examples for a particular channel or register.

Resolve all paths from the repository root. If the references are unavailable, stop and ask for them rather than reconstructing the brand from memory.

## Workflow

1. Identify the register: marketing/editorial, course/teaching, product UI, or long-form.
2. State the section's job and intended reader in one sentence for yourself.
3. Read `brand/FACTS.md` and list the claims the draft may use.
4. Determine the one actual idea. Do not start prose until you know what the section is trying to say.
5. Draft in the Pedanyan voice. Use controlled provocation only when it sharpens the idea.
6. Run the anti-fluff check. Remove slogans, repeated contrasts, fake urgency, generic startup language, and unsupported praise.
7. Run the genericness test: could another design school publish the paragraph unchanged? If yes, add a specific fact, method, example, observation, or point of view.
8. Run the idea test: does each substantial sentence contain information or reasoning? Remove sentences that carry only tone.
9. Verify every factual claim against `brand/FACTS.md` or a named project source. Ask for confirmation when needed.
10. Shorten. Keep the idea and remove the performance around it.
11. Output final copy. Include a separate fact note only when the user needs to approve or source a claim.

## Register control

- Marketing/editorial: use the full voice and no more than one strong provocation per major section.
- Course/teaching: explain what to notice, do, test, or defend.
- Product UI: use plain functional language from `brand/CONTENT_RULES.md`.
- Long-form: build an argument from observations, examples, questions, and counterpoints.

## Boundaries

- Never invent facts, testimonials, outcomes, dates, counts, partnerships, or credentials.
- Never turn placeholder testimonial data into a real claim.
- Never add a cultural reference only to sound sophisticated.
- Never make every heading clever.
- Prefer evidence to adjectives and decisions to slogans.
